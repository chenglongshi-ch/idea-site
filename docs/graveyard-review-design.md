## 1. 白话版设计（三句话）

1. **评审 = 一个主持人 + 几个「职业病眼」agent**：每个 agent 不是扮演性格，而是分管一类死法（产品被砍型/startup 失败型/技术被升级淘汰型…），看你的想法时只找「这类死法会不会发生在你身上」，每条担忧必须指着坟场里具体的尸体说理。
2. **学习 = 语料 + 经验笔记越滚越厚**：不训练模型；每次评审后强制写笔记（或声明这次没什么可学），下次评审把坟场数据+笔记一起带上——「学」=材料变多，不是参数变强。
3. **整理 = 笔记自己防烂**：攒够 N 条同型观察才压缩成规则（琐事永远不触发）；新旧规则打架不许悄悄覆盖，必须分家并互相点名；每条规则记「哪次用过、判对没有」；坟场数据一刷新，旧规则批量标过期回测。

## 2. 评审面板（A 路结论的直接应用）

**骨架抄 Tree-of-Concerns 三件套**（2026-08，precision +79%）：怀疑人格 × 类别透镜 × 交叉复查——它评审论文「未声明的局限」，与本站「评审想法未言明的死法」同构，且同为单份材料全量塞无检索。

- **人格 = 死因透镜，不是性格**：killedbyai 六 deathType 映射分工——产品人格管 product-killed/feature-removed、增长人格管 startup-failed、技术人格管 model-upgrade、平台依赖人格管 killedBy 依赖链。人格名只是让输出可读的皮。
- **首版档位（P1 人裁 2026-09-27）：5 人格 N+1 流水线**——五透镜独立调用互不见面不辩论 + 1 次汇总，成本约 ×6（用户裁质量档）。透镜从六 deathType 映射：产品砍杀/功能移除/创业失败/模型升级/平台依赖。单调用 SPP 式（3 人格+主持人一次调用）**降为降级备选**（成本敏感/流水线故障时回退）。
- **保分歧，不辩论不投票**：每视角一列论断（严重度+引用坟场条目+deathType 语境标注——大厂砍杀逻辑 ≠ solo 想法死法，graveyard-compare §4 诚实边界）；主持人只归纳不表决；**作者人裁终审**（采纳哪些预警是想法作者的决定）。
- **诚实边界进报告模板**：首版定位「撞车提醒+死因视角」，不是判生死。

## 3. 学习环（Reflexion 式经验文件，B 缺口处靠首战校准补证）

```
每轮评审 → decide-and-declare（写笔记 or 显式声明「本轮 skip，因为…」——沉默即违规）
         → 笔记条目 = 结论 + 可溯源证据（评审 run_id）+ 数据底座截至日期 + confidence
         → 下轮评审：坟场语料（截至日期新的）+ 经验笔记 一起进上下文
```

- **三层结构**（C 路 §综合）：
  - **写层**：如上，强制二选一。
  - **整层**：定量阈值触发压缩（GA 式：同型观察攒够 N 条才合成规则——防单例过拟合）+ 定期 consolidation（闲时批量去重合并，**硬预算逼库容**：条数/token 上限，超限必须压缩）。
  - **腐化层**：冲突 → forced fork（建接替条目、旧条目标 superseded、互链——**绝不静默覆盖**，这是公开先例的真空档，抄本机 kb 协议）；用量+结果回写（每条记「哪轮用过+判对没有」——先例只记「被检索」不记「被证对」，同为空白自建）；last_reviewed 时点戳 + 库龄审计；清理走硬规则（last_used>N ∧ 引用=0 ∧ 不在豁免表 → 可回滚 archive），不做「建议删除」死信队列。
- **agent 无人裁的三补丁**（C 路 Q4）：建件=计数门（≥2 次复现+证据引用）代替判断门；升格=证据齐自动升+git 可回滚（或月度人审 checkpoint）；审计报告必须带 actor（预算内自处或升人）。
- **坟场特有加持**：每条经验挂数据截至日期——坟场语料刷新（killedbyai 周级活跃）即批量标 stale 回测旧规则。

## 4. 首战校准（补 B 缺口的机制）

首个真实想法跑评审时做 A/B：同想法「带经验文件 vs 裸语料」各评一次，人工比对论断质量差异——学习环是否兑现价值由此定去留（适应度声明：怎么算合适=带经验版论断更具体/更少幻觉引用；不合适=砍到裸 MVP 全量塞单调用）。

### 6.1 归档——保留思考产物，不留原料档案（2026-09-27 用户裁定）

用户原话：「只需要每个agent 自己去看去思考，而不是保留全部数据，比如满清灭国是因为什么主要原因等等，而不是记录整个满清的历史」——**保留蒸馏结论层，不留原料层**。

| 数据 | 归法 | 说明 |
|---|---|---|
| **坟场源数据**（graveyard.json 128 条） | **不归档**（裁定） | 评审时 agent 直连源拉**当期**数据（通道=api.github.com contents API，2026-09-27 实测可用；killedbyai 主机直连超时已知）。lineage `data_as_of` 只记「看的是哪天的数据」——记时点，不存本体 |
| **分析产物**（analysis.md，站仓槽位 P3 待拍） | **git 即归档** | 思考产物层=用户要保留的「灭国主因」层。**引用即最小快照**：analysis.md 引用条目时自带条目名+deathType+关键句——报告自身承载证据痕迹，原料事后改版不失可读性；CC BY 署名在报告层随引用走 |
| **经验库**（外部侧，P2 待拍） | 文件+git，supersede 软删不物理删 | 同为思考产物层，被本裁定强化——经验库就是「主因」层，原料看完即弃 |

**代价与缓解（不存快照）**：原料源事后改动/删条目，「当时的完整数据」不可复现。缓解=引用即快照的最小粒度；真需复现时 killedbyai 源 repo 自带 git 历史可指认。

**回测改写**：原「新旧快照 diff 批量标 stale」→「**agent 重看新数据对照旧结论**」——每次评审天然发生（拉当期数据+带旧经验=活的回测），零快照基建。

### 6.2 查询——三个消费方，各走各的路

1. **评审系统查自己**（内部，无服务端）：**每次评审直连源拉当期 128 条**（api.github.com 通道，graveyard-compare 已裁全量塞合法）+ 经验库文件进上下文——「每个 agent 自己去看」的落法，不落本地数据档案；>300 条触发 bge-small-zh 检索（届时才需本地缓存，触发再议）。
2. **AI/访客查站**（外部，R3 零后端查询面 Q1-Q4）：
   - Q1 llms.txt ✅ 2026-09-27 已落（构建期自动派生）；
   - Q2 想法页 `.md` 镜像（llms.txt 规范 v2「detail behind links」正解；内容源本就是 markdown collection，构建期白拿）——**待复活**（原 ai-query 死产件重做）；
   - Q3 `/feed.json`（JSON Feed v1.1，唯一有规范依归的站级 JSON 列表端点，与 rss.xml 并挂）——待复活；
   - Q4 `/ideas.json`（自定义结构面：status/tags/demo 直链，llms.txt 内声明发现；**分析产物在场时条目带 `review: {as_of, personas}` 指针**——AI 查列表即知哪些想法有坟场对照，深读走想法页）——待复活；

3. **跨想法问「这类死因命中过哪些想法」**（未来，触发式）：分析产物攒到 ~5-10 个才有查询价值；落法与 llms.txt 同构——构建期从各 analysis.md 派生 `/reviews.json` 索引，零运行时。不预做。
