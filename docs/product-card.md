# 产品卡：想法展示独立站

> 一页纸说明，读者 = 第一次来的访客与 AI。内容全部提炼自仓库内已有文档（前提审计 `.claude/premise-audit.md` 与功能定稿 `docs/spec-site.md`，2026-09-23），本文只做合成、不含新决定。

## 是什么

一句话：每个想法一个网页——想法原文 + 一个能直接玩的 demo（demo = 把想法做成的可交互演示页）。

三句展开：

1. 想法不只躺在笔记里，而是连同它的 demo 一起挂在一个自建的公开网站上（独立站 = 自己域名下、自己可控的网站）。
2. 访客——人或 AI——都能浏览每个想法、在页内直接试玩 demo、留下反响（评论、反馈）。
3. 站是静态网站（静态 = 纯文件构成、无服务器后台，运行成本约等于零），想法以 markdown 文件维护，新增一个想法就是加一个文件。

## 给谁 / 为什么

- 给想法作者：原话「对于一个想法来说，我不清楚如何成功或者反响怎么样」——站让「反响」有了落脚点。
- 给访客与 AI：原话「去让别人或者 ai 查询到」——站是可被定点查询的载体，想法集有固定地址，不散落在各平台。
- demo 能力对应原话「需要有给想法变成 demo 的能力」：一条脚本调用 AI 模型，把想法直出成单文件 HTML 演示页。

## 为什么是独立站

备选方向两个不选（2026-09-23 调研后定案）：

- 平台优先（先挂 Product Hunt 等已有平台收反响）：平台数据不可累积、AI 无法定点查询你的想法集——反响不落在自己手里。
- 工具优先（先装工具把「想法→demo」跑熟再说）：第一需求是被人查到，没有发布面的 demo 验证不了「反响」。

定案：独立站为家 + 轻量 demo 先行 + 平台当放大器（平台只在发布时刻用一次，不当家）。

## 现在能干什么（本地阶段）

本地四类页面：

1. `/` 首页：想法卡片列表（标题 + 一句话 + 状态标签 + 日期）。
2. `/ideas/<想法名>/` 想法页四部分：问题与方案（300 字内）＋ 页内可玩 demo ＋ 更新日志 ＋ 评论区占位（本地不挂）。
3. `/demos/<想法名>/` 纯 demo 页：无正文干扰，直链打开即玩。
4. 404 页（框架默认）。

新增一个想法的四步：写想法条目（状态 = 萌芽，首页即见）→ 跑脚本生成 demo（AI 模型直出，产物自带「由哪个脚本、哪个版本生成」的记录）→ 想法页补正文与更新日志（状态 → 在验证）→ 本地起服务，在真实浏览器里过一遍（页面表现只认真实浏览器，读代码看不出来）。

想法状态三档：seed 萌芽（仅想法）/ growing 在验证（有 demo）/ shipped 已做成。

## 路线

- 现在：用第一个真实想法把「想法 → demo → 挂本地站」整条链在本地跑通。
- 上线预留件（本期一律不做，发布时一次挂上）：评论区、访问分析、「我想要这个」按钮、llms.txt（给 AI 看的站点索引文件）、RSS/sitemap（订阅源与站点地图）——都是零成本或低成本的标准件。

## 成功标准

- 方向（前提已经一手核实）：反响可发现、可查询——想法被人看到、被 AI 收录引用的机制（llms.txt、robots 爬虫规则、搜索引擎收录）零成本可行；静态站零运行成本。
- 刻意不设数字目标：「反响」怎么判定（访问量 / 评论 / AI 引用）尚未定案，属待验证项，不虚构指标。
