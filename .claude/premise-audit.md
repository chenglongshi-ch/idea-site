# 出题层前提审计（premise-audit）

- run：20260923T081530-e24b（五路调研完毕后首次人裁提问）
- 依据：kb `underspec-prior-collapse`（采集先于选项生成＝出题层坍缩）
- 本文件在提问前落盘；问项若变，本文件随之更新。

## ① 用户原话（愿景逐字引用）

1. 「对于一个想法来说，我不清楚如何成功或者反响怎么样」
2. 「现在我需要一个独立站或者别人有的产品，去让别人或者ai查询到」
3. 「另外需要有给想法变成demo的能力」
4. 「我这边可以提供https://platform.sensenova.cn/register的模型，以及agens的模型」
5. 「去研究吧」「注意多agent并行」

## ② 备选框架（≥3，含不推荐的）

- **框架 A（本次推荐）**：独立站为家 + 轻量 demo 先行 + 平台当放大器。
  站收想法与反响（可累积、AI 可查），demo 用轻量路线先实测模型手感，Product Hunt/BetaList 以后只当一次性脉冲。
- **框架 B（不推荐为主案）**：平台优先——想法先挂 IdeasAI/Product Hunt 等已有平台收反响，独立站后置或不建。
  不推荐理由：纯想法平台无留存反例（Kernal 域名已死，调研实证）；平台数据不可累积、AI 无法定点查询你的想法集；「独立站」是用户原话明示的形态意愿。
- **框架 C（不推荐为主案）**：工具优先——先装 Dyad/AGenUI 把「想法→demo」管线跑熟，发布面后置。
  不推荐理由：用户第一需求是「让别人或者 ai 查询到」，没有发布面的 demo 验证不了「反响」；且模型代码质量未实测，先重投入工具有本末倒置风险。
- **框架 D（最小变体）**：不建独立站，想法写成 GitHub 仓库集 + Issues 收反馈。
  欠缺：仍是「建一个可发现的家」，只是换成代码托管形态；对非开发者访客和 AI 爬虫都不如独立站直给。

## ③ 本问隐含前提清单（已核/未核）

已核（2026-09-23 一手或交叉验证，见 research/ 五份）：
- 商汤 OpenAI 兼容 + 免费滚动额度、glm-5.2/flash-lite/u1.5-fast 可用（sensenova-platform.md）
- Agnes 文本/图/视频可用（vedio CLAUDE.md + vedio-assets.md）
- llms.txt/robots/必应收录等可发现机制零成本可行（ai-discoverability.md，OpenAI/Perplexity 官方页一手）
- Dyad 自定义 OpenAI 兼容 endpoint（demo-generators.md 浏览器复核）
- 静态站零运行成本（precedent-products.md）

未核（本问不依赖其成立，但影响后续细化）：
- 受众是谁（中文/英文、开发者与否）→ 影响部署位置与平台选择
- 「反响」的判定标准（访问量/评论/AI 引用）→ 影响统计件取舍
- 想发布想法的类型（工具/内容/游戏）→ 影响 demo 形态
- 模型写代码的真实质量 → 轻量路线第一步即实测
- 搜索/AI 收录时效 → 平台方行为，只能上线后观察

## ④ 推翻选项（当前方向本身可能错了）

「不做独立站——想法验证换个活法」：认为「想法阶段建站=过早基础设施」，或担心想法公开被抄；改为私下快速做 demo、直接找目标用户小范围试，反响从人来不从站来；甚至先挑一个想法做到 ship 再谈门面。
选它=本次调研归档备用，不搭站，另开小方向。

# 增量审计：视觉/功能档位翻案问（2026-09-26）

- run：20260926T211205-323e 尾段（V8 走查否决 design-spec ⑥ 朴素线后的档位人裁）
- 依据：同 kb `underspec-prior-collapse`；采集已完成（research/precedent-products.md 增量 + neal.fun/uneed/swyx 当日实机截图）先于本问选项生成。

## ① 用户原话（逐字引用）

1. 「这个前端的设计实在是太差劲了，你看看其余的都是怎么做的？功能等等，为什么这么简单」（2026-09-26，V8 位实机走查否决）
2. 「你先做出效果吧，之后我在看效果」（同日，验收模式——形态只认实物）
3. 立项愿景沿用：「现在我需要一个独立站或者别人有的产品，去让别人或者ai查询到」+「另外需要有给想法变成demo的能力」（2026-09-23）

## ② 备选框架（≥3，含不推荐的）

- **框架 A（本次推荐）**：现代产品脸——成体系配色（含暗色）+ 开场定位语 + 卡片带 demo 首帧截图 + 状态/标签强化 + 搜索过滤；网格自适应。对标 uneed/swyx 密度，用「demo 截图当脸」替代插画产能。
- **框架 B（不推荐单独走）**：neal.fun 全网格大卡——一想法一大卡、首帧当主视觉。视觉冲击最强，但首页一屏信息量最少，想法 <10 时页面空；neal.fun 的插画产能我们没有，全靠截图撑大卡单调。
- **框架 C（不推荐）**：保守微调——保单列，只加定位语+缩略图+配色升档。不推荐理由：用户刚否决的就是这个档位的存在前提（「太差劲」「为什么这么简单」），再投最小改动大概率二次不过目。
- **框架 D（隐性框架，点名排除）**：不改视觉只堆功能——用功能密度解释「简单」。原话同时点了「功能等等」，但首因是「设计太差劲」；只堆功能不动脸面治标不治本。

## ③ 本问隐含前提清单（已核/未核）

已核：
- 用户否决的是当前形态本身（实机走查，非文档评审）——V8 位有效裁定
- 「简单」的两层来源均为当时主动裁定（design-spec ⑥ + spec §6 功能推迟），非能力缺失
- neal.fun=人设+插画网格 / uneed=暗色产品卡+logo 脸 / swyx=搜索+过滤库（2026-09-26 一手截图）
- demo 首帧可截（demo 为本站静态文件，浏览器可达；E1 demo 已实嵌）

未核（本问拆解对象或影响落地）：
- 「太差劲」里视觉 vs 功能的权重占比（原话两者都点了）
- 用户暗色/亮色偏好（未问过，A 框架默认双主题或暗色待定）
- giscus 评论区需要用户建公开 GitHub 仓库（意愿未核）
- demo 首帧截图管线未搭（机制可行，工具链属新增活）
- 站仍为本地（localhost），视觉投入在「发布」前的优先级是否过高——翻案 ⑥ 但不翻 §6 范围裁定也成立

## ④ 推翻选项（当前方向本身可能错了）

「重审『独立站』本身」：若对站的失望其实指向「想法验证不必自建门面」——回到立项时被裁掉的平台优先线（想法挂 IdeasAI/uneed 等已有场域收反响），站只留极简单页或干脆不建。判别信号：用户若连 A 框架的实物都不想看，或反复表达「做站不值」，则方向层翻案。选它=本期视觉翻案作废，另开方向审计。
